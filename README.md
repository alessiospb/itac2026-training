# ITAC — тренировочный финал

Вы пришли в команду Training Shop. UI работает, но унаследованным тестам и CI нельзя доверять. Ваша задача — привести автоматизацию в состояние, которое можно передать команде.

Это самостоятельная симуляция, а не официальный проект конкурса. Приложение локальное; аккаунты и внешние сервисы для него не нужны. Случайные задержки имитируют обычную асинхронную работу UI и сети. Приложение не подкручивает результат под тесты.

## Начало работы

Требуется Node.js 22+ и npm. В Windows PowerShell при запрете npm.ps1 используйте `npm.cmd` и `npx.cmd` вместо `npm` и `npx`.

```sh
npm install
npx playwright install chromium
npm test
```

Playwright сам поднимет сервер. Для ручного исследования: `npm start`, затем http://127.0.0.1:4173. `npm run test:ui` открывает UI Mode, `npm run report` — HTML-отчёт.

После установки сохраните созданный `package-lock.json` в Git и используйте `npm ci` для последующих установок и CI. В подготовленном окружении установка была заблокирована ошибкой сертификата npm registry (`UNABLE_TO_VERIFY_LEAF_SIGNATURE`), поэтому зависимости и браузеры здесь не проверены. Не отключайте TLS: настройте доверенный сертификат вашего прокси или используйте окружение с рабочим доступом к registry.

**Начальный набор намеренно содержит дефекты. Падения, нестабильность и ложные зелёные результаты — часть задания.** Не читайте `mentor/HINTS.md` до собственной диагностики.

## Условия тренировки

Рекомендуемый лимит: 3 часа. Первые 20–30 минут потратьте на исследование и исходный запуск. Зафиксируйте исходное состояние в Git перед изменениями. Самостоятельно создайте репозиторий GitHub, если хотите отработать Actions и Pages.

Можно менять конфигурацию, тесты, структуру и CI, добавлять зависимости. Приложение в `app/` считайте продуктом другой команды: дефекты продукта описывайте отдельно, не меняйте его ради зелёных тестов. Не заменяйте UI-проверки API-вызовами. Не убирайте асинхронные задержки.

## Требования продукта

- Каталог содержит Mechanical Keyboard ($89), Wireless Mouse ($35), Studio Monitor ($249).
- Поиск нечувствителен к регистру; отсутствие совпадений показывает `No products found`.
- Добавление увеличивает количество товаров в корзине; повторное добавление разрешено.
- Удаление удаляет одну позицию, сумма пересчитывается. Пустая корзина блокирует Checkout.
- Корзина сохраняется после перезагрузки в рамках одного браузерного профиля.
- Оформление требует корректный email и адрес длиной минимум 5 символов после удаления пробелов по краям.
- Купон `SAVE10` уменьшает итог на 10%; неизвестный купон показывает ошибку и не даёт скидки.
- Успешный заказ получает номер `ORD-…`, показывает подтверждение и очищает корзину.

## Что сдать

1. Стабильные, независимые UI-тесты с понятной структурой и проверками результата действий.
2. Новые проверки: поиск без результатов, удаление, пустая корзина, сохранение корзины, валидация, купоны и успешный заказ. Приоритет и глубину покрытия обоснуйте.
3. CI, который достоверно сигнализирует о падении и сохраняет диагностические материалы.
4. Пять полных зелёных запусков подряд **без retries**, без исключения проблемных тестов. После изменения кода начинайте серию заново. Зафиксируйте команды, commit SHA, время, число passed/failed/skipped и ссылки/пути к отчётам каждого запуска.
5. `REPORT.md`: исходные проблемы, причины, изменения, покрытие, доказательства пяти запусков, оставшиеся риски. Отдельно укажите, какие ошибки относятся к продукту.
6. Для полного сценария: GitHub Actions и публикация HTML-отчёта через GitHub Pages; ссылка на баг-репорт в Jam.dev и тест-кейсы/результаты в SpiraTest, если сервисы доступны. Не загружайте секреты в репозиторий.
